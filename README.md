# Kotlin Multiplatform Template

A modular starter template for building **Android and iOS applications
with Kotlin Multiplatform and Compose Multiplatform**.

The goal is to provide a reusable foundation for new projects, with a
clear module structure and a few common infrastructure pieces already in
place. Clone the repository or use it as a GitHub template, then adapt
it to your application.

## What's included

-   **Compose Multiplatform** for shared UI.
-   **Kotlin Multiplatform** targets for Android and iOS.
-   **Navigation 3** with a feature-registration approach.
-   **Ktor** networking infrastructure in a dedicated core module.
-   **Koin** for dependency injection.
-   A small `feature/home` example showing how a feature can define a
    destination, register its navigation entry, and provide a screen.

### Module responsibilities

  -----------------------------------------------------------------------
  Module                              Responsibility
  ----------------------------------- -----------------------------------
  `:androidApp`                       Android application entry point

  `:shared`                           Shared app entry point, app-level
                                      composition, theme,
                                      dependency-injection setup, and
                                      assembly of navigation features

  `:core:navigation`                  Navigation abstractions, navigator,
                                      and feature registration contract

  `:core:network`                     Shared networking infrastructure
                                      built around Ktor

  `:shared:feature_home`              Example feature demonstrating a
                                      screen and navigation registration
  -----------------------------------------------------------------------

The `feature_home` module is intentionally small. Use it as a reference
when creating your own feature modules.

## Architecture principles

This template starts with a few simple boundaries:

-   **Features own their screens and destinations.** A feature registers
    its navigation entries and serializers through the navigation
    contract.
-   **The shared app module assembles the application.** It collects
    feature registrations and chooses the initial destination.
-   **Navigation is centralized.** Feature screens communicate through
    callbacks; the app layer routes those callbacks through the shared
    navigator.
-   **Core modules provide reusable infrastructure.** Features should
    depend on the core capabilities they need rather than reimplementing
    them.
-   **Keep modularization purposeful.** Add modules when they establish
    a useful boundary, not simply to increase the module count.

A simplified dependency direction is:

``` text
                 :androidApp
                      |
                   :shared
                  /       \
       :core:navigation   :feature:profile
                ^              |
                |______________|
```

`:shared` assembles the app and depends on the feature modules and core
infrastructure. Feature modules depend on the navigation contract, not
on `:shared`.

## Supported targets

The template is configured for:

-   Android
-   iOS devices (`iosArm64`)
-   iOS Simulator on Apple Silicon (`iosSimulatorArm64`)

The Intel iOS Simulator target (`iosX64`) is not included in the active
setup. Add it if your team or CI environment needs Intel simulator
support.

Building and signing iOS applications requires macOS and a correctly
configured Xcode installation.

## Getting started

1.  Select **Use this template** on GitHub to create your own
    repository, or clone this repository.
2.  Open the project in Android Studio with Kotlin Multiplatform
    support.
3.  Allow Gradle to sync and download the required dependencies.
4.  Update the project name, application ID, namespaces, and package
    names to match your app.
5.  Review the version catalog in `gradle/libs.versions.toml` and adjust
    dependency versions as needed.
6.  Run the Android application.
7.  To build and run the iOS application, configure Xcode and open the
    iOS integration provided by the project.

> The exact run configuration and iOS integration depend on the project
> files generated by the KMP wizard. Keep those files from your project
> when adapting this template.

## Adding a feature

Use `feature_home` as a small example:

1.  Create a new feature module, such as `:feature:profile`.
2.  Add the module to `settings.gradle.kts`.
3.  Add a dependency on `:core:navigation` if the feature needs to
    register Navigation 3 entries.
4.  Define the feature's destination and screen in the feature module.
5.  Implement the `NavigationFeature` contract to register its entries
    and serializers.
6.  Add the feature module as a dependency of `:shared`.
7.  Register the feature in the app's navigation feature list in
    `shared`.
8.  Connect screen callbacks to app-level navigation actions.

Keep feature modules independent of `:shared` to avoid circular
dependencies.

## Customization checklist

Before using the template for a real application:

-   [ ] Change the root project name and application identifiers.
-   [ ] Replace example package names and namespaces.
-   [ ] Update app name, launcher icon, and platform metadata.
-   [ ] Remove or replace the example Home feature.
-   [ ] Configure environment-specific API endpoints and secrets
    securely.
-   [ ] Add the database, persistence, and other modules your app
    actually needs.
-   [ ] Add tests for your app's navigation, domain logic, and data
    layer.
-   [ ] Configure signing, CI, and release builds.
